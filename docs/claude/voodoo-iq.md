## Server (the server is the referee)
- Items generated and scored in Supabase Edge Functions (`supabase/functions/`, TypeScript/Deno). Client gets render params (`display`) only; answer keys stay in `responses.answer_key`.
- `_shared/`: `rng.ts` (mulberry32; state is one int32 in `sessions.state.rng` so adaptive tests resume), `irt.ts`, `gens/` (27 generators; `gens/data.ts` extracted verbatim from prototype: re-extract, don't hand-edit), `engine.ts`, `standings.ts` (gates), `session.ts`, `http.ts`.
- Functions: `session-start`, `item-answer`, `session-finish`, `blitz-submit`, `profile-save` (clients can't write `profiles`), `leaderboard`. Each has `index.ts` (just `serve`) + `handler.ts` (logic; request/response shapes in header).
- Tables + RLS: `supabase/migrations/20261003000000_voodoo_iq.sql` (+ `sessions.state`, `profiles_public` view). Clients read leaderboard tables; nothing client-writable.
- Tests (`supabase/functions/_tests/`, Deno): `gens_test` (every generator d 1..10 en/es: exactly one correct answer), `parity_test` (port vs prototype JS seed for seed), `engine_test`, `functions_test` (handlers on in-memory `FakeDb`). Run `deno test --allow-read --allow-env supabase/functions/_tests/` (`GEN_SEEDS=1000` ~2 min).
- Deviations (2026-10-13, parity test skips them: `DEVIATES` in `parity_test.ts`): `natodd`/`natquick` build creatures with exactly ONE trait splitting 4-vs-1 and every other trait same-on-all or 3/2 (`natOddItem`, `loneCreatures` checks every candidate rule, incl. values held by 1 or 4); `natclass` accepts only the chosen rule as an explanation of the examples; `anagram` never repeats a word in a session (`ctx.used`, keys `ag<word>`). Client: chord clip is triangle + staggered, anagram has a Submit button, `Art.colorblind` swaps cube/creature colours, leaderboard `board:"player"` feeds the name-tap card.
- **Added generators (owner, 2026-10-25: ~60 new question types straight into the live test, no separate unpublished test; sample page "IQ Question Lab" artifact).** Not in the prototype, so no parity: `gens_test` checks them through `_tests/gens2_checks.ts`. Old packs can't draw them, so the game sends `gv` (generator version, `Items.GV`) with session-start; the server stores it in `sessions.state.gv` and `engine.ts secGens(sec, gv)` adds a version's generators only for that client (no gv = 0 = exactly the prototype's lists, so parity and old packs are unchanged). Within a section the prototype's generators keep half the weight; the added ones share the other half. IQ tests only: Blitz batches stay the prototype's. v1 = second LOG set (`gens/log2.ts`): symsum, scales, ordering, letters, funcmachine, operators, fraccmp, wordprob, dice, sudoku. v2 = second SPA set (`gens/spa2.ts`, checks in `_tests/gens_spa2_checks.ts`): paperfold, cubenet, gears, mirror, countshapes, cubecount (heights never grow toward the viewer, so no cube hides; drawn with `Art.tv_iso(..., marks = false)`), direction, pieces. v3 = second LIN set (`gens/lin2.ts`, hand-written EN and ES banks in `gens/lin2_data.ts`, 3 tiers: d 1-3 / 4-7 / 8-10, no repeat within a session via `ctx.used`; checks + bank test in `_tests/gens_lin2_checks.ts`): remote (missing link), synonym, cloze, unscramble (tiles; capital first and full stop last pin the order; every other valid order is listed in the bank), proverb, inference. Meaning can't be machine-checked: new bank items need a human read for exactly one right answer. v4 = second MUS set (`gens/mus2.ts`, checks in `_tests/gens_mus2_checks.ts`; clips in `voodoo_iq_audio.gd item_clip`, all synthesized): rhythm, transpose, beat, contour, cadence (ends on the key note vs not; harder = ends on another note of the key chord), consonance (smooth = no semitone, whole tone, tritone or 7th). Rendered clips were measured with numpy (pitches, onsets, click offsets) before shipping. v5 = second NAT set (`gens/nat2.ts`, checks in `_tests/gens_nat2_checks.ts`): inherit (each varied trait from one parent; examples rule out every other rule), foodweb (a connected piece of one realistic web; only questions with one clear first effect; `webClear` keeps arrows from running behind other animals in the client's 600 x 340 drawing), idkey, camo (`Art.creature(..., card = false, tint)`), spotdiff. v6 = second KIN set (`gens/kin2.ts`, checks in `_tests/gens_kin2_checks.ts`): gonogo, pursuit, trace, tapbeat, dragfit. Pass / fail trials like tap / timing: the arena (`KinArena` subclasses in `_items.gd`) submits what it measured and new key kinds judge it (`ge` = at least, `le` = 0 to at most; registry.ts). tapbeat scores taps against click time + `AudioServer` output latency (phone audio lag; not yet checked on a phone). A real-time bot (good play must pass, bad play must fail) was run on every trial at d 2 and 9 before shipping. v7 = second EXI set (`gens/exi2.ts`, banks in `gens/exi2_data.ts`, checks + bank test in `_tests/gens_exi2_checks.ts`): wason (answer = card numbers to turn, sorted, "0,3"; d 1-3 people / parcels, d 4-7 letters and numbers, d 8-10 "does not" / "only if" / number-side wordings with 6 cards; the check re-reads the rule text), necsuf (rule templates per domain; the check classifies the wording), assume, contradict (banks), crt (think twice: new numbers each time). Their 💡 examples come from `wx_<gid>` lines in `voodoo_iq_more.json` (`_add_example`). Their text is built server-side in the player's language (rioplatense ES, voseo, like the prototype). v8 = the Self test (engine.ts `selfGens`, `recallSlot`): it also draws the added LOG / SPA / LIN / NAT / EXI types (not MUS: sound; not KIN: speed trials), the prototype's `SELF_POOL` keeping half the weight; and items 4, 11, 18... (every 7th from the 4th) are `recall` "Will you remember?" trials (`gens/self2.ts`, checks `_tests/gens_self2_checks.ts`): study 3-6 word pairs (EN/ES word bank at the same index), guess how many you'll get, then pick each first word's partner from the partners + 2 unstudied words. No confidence is asked after it; the client sends `{ g, picks }`, item-answer stores `{ g, s, n }` in `sessions.state.recall` (no schema change), and the result's SELF entry gets `recallN`, `recallErr` (mean |guess - got| / pairs) and `recallBias`. They COUNT toward the Self score (owner, 2026-10-25): `recallTheta` = (0.2 - err) / 0.1 and the confidence-AUC theta (`confTheta`) are averaged by precision, recall se = 1.5 / sqrt(trials) (min 0.5). These norms (`RECALL_NORM` in engine.ts) are PROVISIONAL guesses: retune them from real players' recallErr. Recall rows stay out of the AUC rows and out of Self's item targeting; `valid` is still the confidence gate. A Self test with no recall trials scores exactly as before. v9 = second INT set (`gens/int2.ts`, banks + story text in `gens/int2_data.ts`, checks + bank test in `_tests/gens_int2_checks.ts`; the Self test draws them too) and the new faces: hairstyles 3..11 (`NEW_HAIR` in `voodoo_iq_art.gd`, ported from the owner-approved Face Lab artifact; its bun was rejected and is not there). gv 9 clients get only new styles: the INT2 gens draw them (`newId`), and `engine.ts restyle()` swaps styles 0..2 for 3..11 on the prototype's face items and on Blitz batches (cosmetic: keys unchanged; blitz-submit's regenerated batch scores the same). Types: flash (blink and you miss it: two faces baked first, the expression shows flashMs = 400..40 ms), smile (real or polite: same mouth, the real one adds cheek raise + lid tightening, cr gap never below 0.3), gaze (what do they want: `gx`/`gy` move the pupils in `Art.face`; 4/6/8 objects drawn by `Art.thing`), intensity (tap least to most, `str` key "2,0,1"), facemem (have we met: study 2-4, line-up of 4/6 with one-feature look-alikes), eyes (read the eyes: 8 states from eye-region units, look-alikes offered from d 5), tom (where will they look: events generated and simulated by `tomRun`; the check re-simulates differently; d 8+ peeks and second-order questions), posture (body language: `Art.figure` from joint values), feel, change, sarcasm, fauxpas, help (hand-written EN/ES banks, 5 per tier; need a human read for one best answer). Tone of voice is left out (needs recordings). Raise `GV` on both sides only with the new views. Audio-recording questions are left out (owner, 2026-10-25).
- Parity test skips natclass per generator too (documented deviation; it was failing at seed 1916209878 before the 2026-10-25 work).
- **topview fix (2026-10-25; prototype bug, players' complaint: 3D professionals scored low).** In the isometric drawing column j runs right to left along the white front edge, but the answer grid draws j left to right, so the keyed "right" picture was the mirror image of the true view from above (and the true view was a distractor). Now `spa.ts tvView` = `tvMir(tvTop)` is right (server only; old packs draw it unchanged). The parity test skips topview; `gens_test` checks the answer against the drawing's own projection. Old answers can't be re-marked (responses keep only u, not the option tapped), so they're left out: new keys carry `rev: 2`, `session.ts KEY_REV` / `scorable()` drop older topview answers from scoring (finishIq, the player card), not from item picking (Self recall slots count every item). `tools/iq_rescore.ts` (owner runs it with the service-role key; dry run unless `--apply`) rescores finished tests in place: section_scores rows updated (day / created_at kept; a section with no answers left loses its row) and `sessions.result` replaced (`rescored` stamp). Next wrongly keyed generator: raise its `KEY_REV`, tag its new keys, rerun the tool.
- Deviation: `melody` rebuilds a melody when no note can change validly. `responses.a/b/c` are float4: never used for math (engine rebuilds from generator + stored key).
- Policy (owner 2026-10-03): no daily limit on ranked IQ (Daily Brain keeps once a day); standings combine last 3 sessions, rank by estimate - 2 SE. Nothing hidden/capped: boards rank by IQ(theta), mark `verified` ✓, `fmt_iq` shows the real number; EAP grid (theta -4..4) bounds IQ 40-160. `standings.ts` stays 1:1 with prototype; policy lives in `leaderboard`. ∞ Endless tests are default (`dur: 0`, no clocks; motor trials keep their speed and the too-fast rule); player taps Finish. ## Client (`scripts/games/voodoo_iq/`)
- `_game.gd` (brain-map home + setup, profile form, runner for IQ Test and Speed Round (Blitz), results), `_items.gd` (one view per generator; emits the value server `checkAnswer` expects), `_art.gd` (prototype SVG drawings as draw calls via viewBox mapping + SVG path parser), `_audio.gd` (tones to AudioStreamWAV), `_api.gd` (Edge Function calls), `_text.gd` + `_data.json`.
- `voodoo_iq_data.json` (STR EN/ES, colours, icons, brain map, palettes) is generated by `deno run --allow-read --allow-write tools/iq_extract.ts`; never hand-edit. Only new client strings and the help card go through es.json.
- `voodoo_iq_more.json` (hand-written EN/ES): `T.t()` reads it first, so it holds the added question types' `gt_/ins_/q_` text and any prototype line that changed (e.g. `ins_pitch`).
- Musical questions replay as often as the player likes, in the test and the Speed Round (owner, 2026-10-25); the client ignores the server's `replays` count.
- Token: `_api.gd` reads `Auth.access_token` and calls `Auth._ensure_fresh_token()`; no APK change needed.
- **Practice answers (owner, 2026-10-25: practice only; ranked tests, Daily Brain and Duels never show answers or a review).** item-answer adds `fb` = engine.ts `practiceFeedback` { seq, u, key, minMs, rapid, timeout, hidden, why } for a practice IQ test; blitz-submit adds `review` (one per answered item) for a practice Speed Round. Client: `_show_feedback` puts a right / wrong card above the answered question (clock paused until Next), `practice_log` keeps every answer, results show 📝 Review answers (list, Wrong only filter, each question drawn again). `Items.reveal` marks the answer: multiple choice lights ✓ green / ✗ red via `ItemView.mc_buttons` (also on grids built later, flash / facemem); wason, intensity and corsi set `reveal_hook`; every key kind has text in `Items.answer_lines`. Motor trials and "Will you remember?" are never drawn again (text only). 🚩 → `item-report` Edge Function: stores { why, value, display, at } as `report` inside that item's `responses.answer_key` (no schema change); list them with `supabase/checks/iq_reports.sql`. **Why (2026-10-25):** every generator sets `Item.why` (EN/ES via `registry.ts say()`, built from its own values, never drawing from the RNG, so items are unchanged; `gens_test` asserts every item has one). It is stored in `responses.answer_key.why` (storedKey) and sent only in practice `fb` / Blitz `review`; the card shows it in a 💡 Why box. Bank types (feel, change, help, cloze, inference, analogy) get a general explanation built from the item, not a per-item one; structured types (series, matrix, scales, gears, tom, wason, crt...) explain the actual working.
- Blitz gets no per-item feedback (client has no keys); score arrives from blitz-submit (a practice run's review comes with it). Runner has ⏸ (clock stopped, question hidden, text size + sound), 🔇 skips musical questions (sent as null, Musical section only), 💡 worked examples for Existential types. 🏆 screen = prototype boards page (home top bar, under Setup, results).
- Width from the visible screen, never 680: `_fit_width()` = viewport width minus safe-area offsets, re-run on `size_changed` (Settings applies text size after `_ready`). Large text on a phone ≈ 600 units. Measuring the root Control is wrong (too-wide content stretches it). Test phone layouts in a phone-shaped window (`--resolution 300x650`).
- Not built: prototype's untimed "Try an example" (needs endpoint), its fonts. Cube stacks use the prototype's 2D isometric drawing (server visibility check uses that projection), not real 3D.
- Test without a release (hub lists from LIVE manifest): `godot --path . res://scenes/games/voodoo_iq/voodoo_iq.tscn`.
