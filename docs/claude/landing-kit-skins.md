# Landing/Home kit, skins, Options/Settings, screen layout

Rules live in `docs/STANDARDS.md` (§1-9). This file = how the code does it.

## Landing kit (`tools/templates/home_kit.gd`)
- The only copy edited; `hub.py sync` copies it to `scripts/games/<id>/home_kit.gd` for every game that mentions it; `hub.py check` fails if a copy differs. Header = how-to. Sudoku (own Home, reference: `sudoku_home.gd`) and Voodoo IQ (brain map) don't use it.
- Landing: ▶ Resume, ⚡ Quick Play (last mode), 🎮 Single player / 👥 Multiplayer -> setup screens (game's `extra` pickers, ▶ Start), ❓ 🏆 🏅 📊 ⚙. Only screen with "← Hub". Every card has 🏠 Home (‹ Back over the pause menu). Pause menu: Resume / Restart / How to Play / 🏆 / 📊 / 📸 / ⚙ Options / 🏠 Home (no Hub). ⚙ Options = app-wide settings + per-game Rotate and Classic/Voodoo. The kit frees the floating SettingsDrawer. Per-game choices in `user://landing_<ID>.json`.
- Game supplies `HomeKit.new({...})`: logo (`_draw_home_logo(c)` using kit `glow_line/rect/circle/text`), accent colour, subtitle, `modes` (`"row"` = difficulty side by side, `"multi": true` = under Multiplayer, `solo_heading`/`multi_heading`, `"extra"` pickers), `save_path` + `resume` (+ `resume_text`), `restart`, `board` (stat the 🏆 ranks; default "Best score"), `online`, `"art"` (`res://games/<id>/landing_bg.jpg`, cropped, darker toward bottom, subtitle outlined). API also `start_mode(m)`, `home.pause()` from the ⏸ button, `neon_theme()` (set as root `theme`), `backdrop()`.
- Kit pauses the tree (PROCESS_MODE_ALWAYS) while Home/pause shows, so a game that starts itself in `_ready()` waits underneath. A mode button un-pauses and calls its action, which must start a fresh game; afterwards the kit asks Settings to re-fit (`_fit_scene`). "Home" from pause saves (`_save_game()`) and reloads the scene. Pauses (and saves) on `NOTIFICATION_APPLICATION_PAUSED` (not focus loss).
- Saves: only Home "New …" buttons delete a save. `_ready()` must NOT delete it: games keep a `started` flag `_ready()` clears; `_save_game()` skips when false.
- Home scrolls by dragging (kit `_DragScroll`); kit buttons ignore the release that ends a drag (`_dragged()`); landscape: shorter logo, three More buttons per row (`_fit_home_layout`).
- Buttons: one neon-blue colour (`HomeKit.BUTTON`), green (`HomeKit.GO`) only for ▶ Start/Resume; per-mode `"color"` ignored. Picked/pressed keep white text. Retro-arcade Classic filter covers the game, never kit screens.
- Backgrounds: card games (`HomeKit.FELT_GAMES`) get green felt, other games dark leather (`media/hub/backgrounds/felt.jpg`, `leather.jpg`; `bg_texture()`); flat colour+grid on apps without them. Arcade games never take them (`HomeKit.OWN_BG_GAMES` = manifest's Arcade category; `check` fails if a new arcade game is missing). Game `"art"` wins.
- Card games: neon cards (dark face, pink/cyan rim); shared `<id>_cards.gd` copies stay identical (Solitaire's `card_view.gd` matches).
- Leaderboard metric: games without "Best score" rank a growing counter; the kit posts it whenever Home shows.
- AIs/same-phone modes exist for most board/card games (vs-computer: Tic-Tac-Toe, Connect Four, Checkers, Reversi, Chess (alpha-beta in a thread), Mancala; 2 Players: Backgammon, Farkle, Morris, Memory, Shut the Box; "one sets, one guesses": Code Breaker, Hangman, Wordle).
- Testing: `godot --headless --path . --script res://tools/crawl.gd -- [ids]` (presses every Home card, offline mode, pause menu, Resume); `tools/shot.gd` drives a scene and saves screenshots (`--resolution 405x720` phone, `720x405` landscape; steps in header). Both play real games: back up user data.

## Skins: Classic (default) + Voodoo
- Landing kit: ⚙ Options -> Look (Classic / 💀 Voodoo, per game, `user://landing_<ID>.json`; default = app-wide skull mode, off = Classic). Game opts in with `_set_skin(name)` (re-skin in place, no reload; online matches continue) and `_current_skin()` if it saved its own choice (Solitaire's `solitaire_style.json`). Classic colours: `HomeKit.CLASSIC` + `reference/art/skins/CLASSIC.md`; no glow, no grid. Pilots: Four in a Row (blue board), Tic-Tac-Toe (paper), Checkers (wood), Solitaire (felt; Voodoo backs = doll). Older `_set_voodoo` games (Reversi, Alien Attack, Gem Match, Bop the Mole) show the same Look row but their "Classic" is still neon. Others: one look until a Classic skin is made.
- Voodoo Mode (`scripts/common/voodoo.gd`, header = how-to): skulls, crossbones, voodoo dolls (button X eyes, stitched seam, pin) drawn in code. One global switch `user://voodoo_mode.json` ("💀 Skull mode" in Options). So far Tic-Tac-Toe (crossbones vs skulls), Connect Four (red skulls vs yellow dolls), Reversi (black skulls red eyes vs white skulls). Pieces keep player colours (stats keys unchanged; only names displayed: "Bones", "Skull", "Doll"). **Load, never preload** (`VOODOO_PATH`, `var voodoo = null`). Opt in by defining `_set_voodoo(on)`. Skin is local: online opponents may see different pieces.

## Options screen + Settings autoload (`settings.gd`, `scenes/hub/options.tscn`, `options_screen.gd`)
- Options: text size, theme, language, skull mode, sound, vibration, keep screen on, account, check for updates, feedback (GitHub issues), Storage, Credits.
- **Text size** via `root.content_scale_factor` (Normal 1.0 / Large 1.2 / Extra large 1.4; new installs Large). `Settings._fit_scene()` measures each new scene (on `SceneTree.scene_changed`) and backs the scale off to fit, never below 1.0. Wordle, Crossword, Anagrams fit ~1.0; Block Drop, Liar's Dice, Blackjack, Morris ~1.1-1.2 (fixed pixel sizes). New UI sizes from the viewport, not 720.
- **Theme** (`Settings.palette()`: `bg`, `text`, `accent`, `link`, `ready`…) covers hub + Options only. Game colours are per-skin.
- **Sound** (`sound_options.gd`, also opened by the in-game Options): Off = mute Master; Volume slider; per-group on/off + volume (`Settings.SOUND_GROUPS`: taps & keys, game sounds, wins & losses, notifications, music). Sliders apply live, save on release (`set_volume(v, save)`), every change plays a sample.
- **Vibration**: Settings connects every `BaseButton.pressed` (`node_added`) to a 12 ms tick; GameInfo buzzes 70 ms on win/loss. Needs `permissions/vibrate=true`.
- **Games never reference `Settings` directly**: `get_node_or_null("/root/Settings")`.
- Drag-to-scroll for button lists: `drag_scroll.gd` (child of ScrollContainer; handlers check `moved`); dialogs over such a list join group `modal_overlay`.
- `python tools/hub.py test` boots Options too.

## Screen edges, ⚙ tab (legacy), resume
- **Safe area**: `Settings._apply_safe_area()` insets each scene's root Control by the camera cutout (`DisplayServer.get_display_safe_area`, min 24 units top in portrait); clear colour black. Lay out from the root's own rect, never window coordinates. Test: `VOODOO_SAFE_INSET="l,t,r,b"` (canvas units).
- **Landscape boost**: `Settings._landscape_boost()` multiplies content scale by 1280/720 when wider than tall. **Gotcha**: root `size_changed` also fires on content-scale change; refit only when the *window* size changed (`_on_root_resized`) or a scene `_fit_scene` shrinks (Block Drop) loops forever.
- Legacy `SettingsDrawer` (`settings_drawer.gd`, no-op stub for old packs; never delete the class): its "❓ How to Play" button, draggable half-transparent ⚙ tab (`user://drawer_pos.json`), `_avoid_controls`, `drawer.set("default_frac", 0.6)`. Panel placed with offsets (`position` on an anchored Control is from its top-left).
- **Resume after Android kills the app**: on pause inside a game Settings writes `user://resume.json`; hub's first `_ready` reopens that game (`Settings.take_resume_scene()`); games with `_save_game` continue.
- Rotate: reloads scene whose `_ready()` re-locks default orientation; `Orientation.override_next()` makes that one lock rotate.
- Android orientation enum: `DisplayServer.SCREEN_SENSOR_LANDSCAPE/PORTRAIT`; always via `scripts/common/orientation.gd`.
